# Libra Governor v0.0.5 — Cooperative Preview (Apple Silicon macOS)

A local monthly budget shared by your Claude Code sessions and subagents, and by your Codex turns **only if you opt in**. **While the Libra daemon and hooks are running correctly**, prompts are admitted or refused up front against a monthly USD cap you set
(`libra-governor shared-budget init --monthly-usd <n> --time-zone <IANA>`). **This is a Cooperative Preview, not a hard spending cap.**

What it is and is not (the five required disclosures, then the fail-open and trust-boundary disclosures):
1. **Admission-bounded (cooperative), not a strict monetary cap.** A prompt is admitted only if the remaining monthly budget can cover its hold, and only when the daemon and hooks answer.
2. **In-turn overshoot is possible.** Spend inside a turn is visible only when the turn stops, so a turn can cost more than its hold.
3. **Codex is not gated by default.** Until you opt in, Codex sessions are neither admitted nor charged by this budget, exactly as in v0.0.4. The v0.0.4 Codex task preflight and receipt output is unchanged and still appears without the marker; only the shared budget is left alone. You can opt in by creating the marker file `<state-dir>/shared-budget.codex` (a plain empty file, e.g. `touch`; a symlink does not count) next to a configured shared budget; from then on Codex prompts are admitted against the same monthly budget and each Codex turn is settled from the turn's recorded usage (a turn that cannot be measured books the flat hold, never zero). There is no gateway hard cap in this release, and opting in does not make the cap strict (see 1 and 2). Opt-in Codex accounting has its own limits, listed below.
4. **Amounts are Libra's list-price-equivalent estimates (or flat holds), never your provider bill or quota, and they are not exact.** The pinned pricing table has known errors in both directions, and they change how accurately the budget admits and refuses prompts:
   - Known gaps fixed in `pricing-2026-11-static-v4` (HORO-2443): the 1-hour cache write is priced at 2x base input, Haiku 5.5 prompts up to 100,000 tokens use the lower official row (v0.0.4 priced them at the over-100k rate, so they were over-accounted by approximately 5x), fast mode (Opus 5.5, Opus 5, Opus 4.8) is priced at its own 2x rows, and `inference_geo: "us"` (Claude 4.6 and later) at 1.1x. A usage report that cannot be priced (fast mode on a model without it, US geo on an older model, an unrecognised value, a contradictory cache split) settles at the flat hold instead of a guess, and a cache write with no TTL breakdown is priced at the dearer 1-hour rate. A Claude model id that is not in the table (for example a newer model released after this build) also settles at the flat hold in hook mode (the optional gateway refuses an unpriced model before forwarding), and the flat hold is a floor, not a price: a large turn on an unlisted model that costs more than the hold is under-counted until the table is updated or a `pricing_overrides` entry is added for it.
   - `service_tier` is not a list-price modifier and is not modelled. An absent `speed` is read as standard and an absent `inference_geo` as global (real hosts always send both; a workspace-default US-only or unreported fast request would book at the base rate). Prices are the official list prices retrieved 2026-11-06; the table is wrong until updated when the provider changes them.

   The cap is a Libra-accounted estimate that can drift from the provider bill either way. It is not a guarantee of matching the bill or of staying under your plan or provider limit.
5. **Accounting boundary.** Only Claude Code sessions and subagents, and Codex turns if you opted in, whose settlement hooks run and whose transcripts or rollouts can be read and attributed are counted. Other executors and unreadable or unattributed spend can settle at the flat hold, be recorded as unattributed, or be missed. Turns around `/compact`, partly flushed interactive turns, subagent files over 32 MiB, and settlement skipped while the daemon is down can also be under-counted or missed. A forward clock jump or time-zone change near a month edge opens the next month's budget early.
6. **Fail-open behaviour when the daemon is unavailable.** With a budget configured, an unreachable daemon makes the prompt-admission hook refuse the prompt (observed in testing with daemon auto-start disabled). The other hooks fail open: tool-call checks are not enforced, and end-of-turn and end-of-session settlement is skipped with only a log line. A skipped settlement may be recovered by a later successful end-of-turn settlement in the same session, or it may never be counted. Prompts whose session id Libra cannot use are never blocked. An absent budget file, or a missing state directory, means no budget is configured and prompts are allowed. A budget file that exists but cannot be used (unreadable, not a regular file, empty or invalid JSON) is a budget that is present but invalid: the prompt is blocked with an explicit reason until the file is fixed or removed.
7. **Libra is NOT a security boundary against a governed agent running under the same operating-system user.** Libra and the agent it governs run as the same user. Any process under that user, including the governed agent, can stop the daemon, edit or delete `shared-budget.json`, or send the daemon requests. The cap is cooperative and not tamper-proof, and Libra offers no protection against an active, adversarial agent running as your user. Keep Libra's state directory in its default private location, and do not place it, or point `LIBRA_GOVERNOR_STATE_DIR`, in a shared location or any location that other users can write to.

What is new in v0.0.5:
- **Opt-in Codex accounting, off by default** (disclosure 3). A turn that Codex kills, or whose final usage record arrives late, is settled or topped up at the next settle; Libra never refunds. `libra-governor doctor` and `shared-budget status` report enrolment, whether the Codex hooks are installed, pricing state and the gaps below.
- **Provider-namespaced budget lanes** (protocol v25). Claude Code and Codex sessions that reuse a session id no longer interact. Run the daemon and the CLI from the same release: a v24 daemon rejects a request that carries a provider, and a v25 daemon built before the Codex hooks rejects the new settle request, which leaves an enrolled install ungated until the daemon is restarted (`doctor` probes for this).
- **Hardening.** `shared-budget` refuses to chmod through a state-directory symlink; reinstalling the Claude Code or Codex hooks from a different binary path repoints Libra's own hooks (including ones written by v0.0.4) instead of adding a second set; a hand-quoted hook command is recognised as Libra's, while a hook command that wraps another program around it (`env`, `cd &&`, pipelines, `nohup`, `sudo`) is treated as yours and left alone; `shared-budget export` labels its capacity as the pool-row value.

Codex limits (apply only if you opt in):
- **Codex hooks run only after you trust them** in Codex's `/hooks`. Untrusted hooks are skipped silently and leave an enrolled install ungated; `doctor` can only say trust is "likely not yet trusted" or "unknown", never "trusted".
- **Only listed Codex models are priced.** Codex turns are priced from pinned OpenAI list prices (standard tier, short context, `pricing-2026-11-static-v4`) for gpt-6.1-sol, gpt-6.1-terra, gpt-6-sol, gpt-6-astra, gpt-6-luna and gpt-5.3-codex; a `pricing_overrides` entry takes precedence. Any other model (including `gpt-5.6-*`) books the flat hold (unmeasured) and is never trued up, and prompts above 272K input tokens are under-counted.
- **Model ids are matched exactly, or with an 8-digit dated suffix (HORO-2366).** A pinned id matches only itself or itself plus `-YYYYMMDD`. A variant such as `-mini`, `-pro`, `-latest`, a Vertex-style `@20250929` suffix or a `[1m]` marker is no longer priced from its parent: it is unpriced, so a Claude turn on such an id books the flat hold or is refused, and a `pricing_overrides` entry now applies to the same exact-or-dated ids only. This applies to Claude and Codex ids alike. Previously a longest-prefix match could price a different model at its parent's rate.
- **Interrupted turns are under-counted.** A Codex turn that is interrupted or aborted writes no usage record, so that spend is not visible. A turn longer than the one-hour hold is settled late on partial usage.
- **Codex subagents are neither admitted nor settled.** There is no mid-turn hold renewal for Codex.
- **Mostly source-derived.** Codex behavior was derived from reading Codex source at tags 0.160, 0.163, 0.164 and 0.165 and from synthetic fixtures. It was then run against one real Codex host (codex-cli 0.163.0, a few trivial turns in an isolated QA home): trusted hooks fire, a turn is admitted and settled from measured rollout usage, the block decision is honoured, untrusted hooks are skipped silently, and a resumed session is booked once per turn. Interrupt, compact and fork behavior, other Codex versions and provider billing were not run.

Other known limits:
- **`shared-budget init --force`** replaces the whole budget file with no backup. Hand-written `pricing_overrides`, the subagent unmeasured charge and soft limits that you do not pass again are dropped, and the turn hold resets to its default if omitted.
- **Hook ownership.** `uninstall` and `install` recognise Libra's own hook commands by shape. A hand-renamed hook command is not recognised, so `uninstall` can miss it and a later `install` can add a second one. In rare cases a wrapper you wrote around Libra's own binary, using an unusual launcher and a relative path argument, can be mistaken for Libra's hook and rewritten or removed; check `settings.json` and the Codex `hooks.json` if you wrap the binary. `install` refuses a binary path containing whitespace or a shell metacharacter, because the host would run such a hook command through a shell and it would silently never run. It also refuses a binary whose file name is not exactly `libra-governor`, because Libra recognises its own hooks by that name and hooks written for another name would be invisible to `doctor` and `uninstall`.
- **Clock anomaly.** After a forward clock jump creates a later month's pool, every prompt is refused (`clock_anomaly`) and there is no repair command. Correcting the clock does not clear it; the recovery steps are in ADR-0026, and deleting `shared-budget.json` pauses the budget.
- **Settlement sweep limits.** The end-of-turn sweep visits at most 64 subagent transcript files and 128 MiB per run, so records can be deferred or lost. A subagent file over 32 MiB is booked at the flat hold and not re-measured.
- **Implausible measured usage is not booked.** Libra refuses any single explicit or extra charge above ten times the monthly cap. A turn settled from measured transcript or rollout usage follows the same bound (never below $1,000): spend under it is recorded in full, overruns included, and is never clipped; a figure above it is treated as a corrupt or forged transcript, is not booked, and the turn settles at its hold flagged unmeasured with reason `usage_implausible` (Claude's watermark advances past the skipped lines so later turns are measured again; those lines are never counted as spend, and a Codex hold with several turns settles whole at its hold if any one of them is implausible, without a later true-up). The skipped figure is written to the daemon log, and the reason shows in the hook log and the aggregate unmeasured-settlement count, not as a separate status field. This concerns only Libra's accounting and does not change what the provider bills. Tracked in HORO-2350.
- **A Claude session that ends without a `Stop` now settles its hold at `SessionEnd`.** (HORO-2440; in v0.0.4 and earlier v0.0.5 candidates the hold stayed reserved until it expired.) `SessionEnd` settles the lane's pending turn hold the way a `Stop` would: the measured amount when the transcript is readable, otherwise the full hold amount, flagged as not measured, so unsettled usage is never booked as zero. A hold that had already expired books only usage that can be measured. Only that session's own lane is touched, and a late `Stop` or a repeated `SessionEnd` books nothing more. A host that is killed before `SessionEnd` fires still leaves its hold until it expires (one hour after its last renewal).
- **Late records.** Late transcript evidence may be recovered by a subsequent Stop or SettleTail where supported, but windows that were already settled are not guaranteed to be re-measured. A turn whose transcript could not be read at settlement is booked at the flat hold; its late lines may be lost (the hold already covers them) or counted again on top of the hold at the next settlement.
- **Flush timing.** Transcript flush timing was measured only against a fake upstream (four interactive samples, plus earlier non-interactive runs). That evidence says nothing about real-provider latency, and no real-provider latency coverage is claimed.

Support: **Apple Silicon (aarch64) macOS only.** x86_64 macOS, Linux and Windows are not supported or verified. The release workflow builds exactly one target, `aarch64-apple-darwin`.

**Uninstall does not restore your Claude Code `settings.json` byte-for-byte.** It removes only Libra's entries and preserves your other keys and hooks, but it re-serializes the file. Install writes a byte-identical backup first (`settings.json.libra-backup-*`); keep it if you need the exact original. Uninstall also leaves timestamped backup files and a `settings.json.horonom-write.lock` file next to your settings: the backups are your rollback copies (keep or delete them), and the lock file is only Libra's own write lock. Local export and prune are local-only; nothing is uploaded. No telemetry.

Not in this release: S11 gateway hard cap, OpenAI Responses gateway, remote upload, strict cross-host cap, enabling any Codex budget control beyond the opt-in marker. No claim is made about real-provider pacing or productivity gains, production-observed correctness, or native Codex budget enforcement.

Known issues in this preview: open dependency alerts concern a Python experiment directory (`experiments/phase0`) that is not part of the shipped binary. `libra-governor uninstall` always suggests `cargo uninstall libra-governor-cli`; if you installed from the tarball, delete the copied binary yourself. The optional local gateway (off by default) had two defects in v0.0.4, both fixed in this preview: `libra-governor gateway token` (the `apiKeyHelper` command) now serves the file named by `gateway.token_path` (HORO-2363), and `libra-governor gateway status` now reflects the real listener instead of printing `State: running` after a startup failure (HORO-2424). `libra-governor doctor` now warns when the gateway config would be rejected (a non-loopback `bind_addr`, an unknown key) (HORO-2364).
