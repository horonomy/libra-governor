# Corrections to the published v0.0.4 release notes

The v0.0.4 tag, its tarball and its `docs/release-notes/v0.0.4.md` are frozen and are not
rewritten. This page records where the published notes, the tagged README and other tagged
documents are incomplete or inaccurate, so a reader of the tag can find the current,
version-specific facts. It is maintained on `main` and does not claim to be part of the tagged tree.

Fixed in v0.0.5 (unreleased): the optional-gateway defects described below for the published v0.0.4 binary (`gateway token` ignoring `token_path`, HORO-2363; `gateway status` and `doctor` saying running after a startup failure, HORO-2424; `doctor` accepting a non-loopback `bind_addr` and unknown keys, HORO-2364) are fixed on `main` (#328, S11f). The statements below stay true of the published v0.0.4 binary.

Status of the Release body itself: the items below marked **(Release body)** were proposed
corrections to the published GitHub Release text. Item 12 was applied to the Release body earlier.
The gateway-status warning in item 18 was added to the Release body on 2026-11-05 on the owner's
approval; the Release tag, assets and prerelease status were not changed. This page states the
facts for everything else.

## Facts a v0.0.4 user should know (verified against the published binary, the tagged source or recorded release evidence)

1. **(Release body)** Uninstall: `libra-governor uninstall --yes` (or answering yes at its prompt)
   deletes Libra's whole state directory, including `shared-budget.json` (the monthly budget) and the
   spend ledger. Without confirmation the directory is left in place. The settings backup and
   `settings.json.horonom-write.lock` files remain next to your Claude Code settings.
2. **(Release body)** The "ten times the monthly cap" refusal applies to subagent, session-end and
   externally submitted charges. A main-turn settlement in v0.0.4 is recorded as priced even above that
   bound (the cap can go negative; later prompts are then refused). v0.0.5 candidates add a separate ceiling
   for implausible transcript usage.
3. **(Release body)** `/compact`: the one recorded observation was an over-count (booked at the flat subagent
   fallback); an under-count is possible but unobserved, so turns around `/compact` can be mis-counted in either direction. A main-transcript window larger than
   32 MiB settles at the flat hold, not only a subagent file.
4. **(Release body)** "No gateway hard cap in this release" is true for the monthly budget. The optional local
   gateway exists (off by default, configured in `config.json`) but is not connected to the monthly budget.
5. **(Release body, optional)** Model ids are matched to the pinned price table by prefix, so a newer id that
   shares a listed prefix is priced at the older entry's rates.
6. The README in the v0.0.4 tag says every hook is advisory-only and that "nothing here blocks". With a
   `shared-budget.json`, `UserPromptSubmit` can refuse a prompt and `PreToolUse` can deny a tool call.
7. The README in the v0.0.4 tag says no binary has been published and v0.0.4 is unreleased; the Apple Silicon
   tarball is attached to the v0.0.4 GitHub Release (a prerelease). See the Install section of the current README.
8. The tarball binary is ad-hoc signed and not notarized. `uninstall` prints a `cargo uninstall` hint for it
   (disclosed in the notes); delete the copied binary yourself.
9. `integrations/codex/README.md` in the tag lists Linux and Windows platforms. The only supported platform is
   Apple Silicon macOS.
10. Gateway configuration (optional, off by default): `token_path` must equal `<state_dir>/gateway.token` because `libra-governor gateway token` ignores the setting (a known defect); the
    session-binding header name and the reservation TTL cannot be set from `config.json`; there is no
    `pricing_overrides` in the gateway config (`shared-budget.json` has its own); the `x-libra-decision` list also includes `unauthorized` and `upstream_unavailable`.
    The historical ADR-0003 text still uses the old `gateway_reservation_ttl_secs` name.
11. ADR-0025 "Publication-time requirement 7" says release.yml builds three targets; the release workflow
    builds Apple Silicon (aarch64-apple-darwin) only. `docs/execution-owner-contract.md` states protocol 15 in
    its IPC section (and 22 later in the same document); the tagged protocol version is 24.

12. **(Release body)** The "Known issues" sentence says "three open dependency alerts" in `experiments/phase0`. On
    2026-11-02 GitHub shows 13 open alerts, all `filelock` in `experiments/phase0/uv.lock` (severities low to high).
    They concern a Python experiment directory that is not part of the shipped binary; the location claim stands,
    the count was wrong.
13. `uninstall` asks for the full word `yes`; `y` declines.
14. **(Behavior to know)** A turn that never reaches `Stop` (you interrupt it, Claude Code exits or crashes, or a
    `SessionEnd` arrives with no `Stop`) leaves its hold, one turn's reservation (default $10.00), open until the
    hold expires after one hour (`HOLD_TTL_SECS = 3600`), unless the same session sends a new prompt (which renews that
    hold instead of adding a second one) or a later `Stop` in that session settles it. `SessionEnd` charges only the
    records no `Stop` counted; it does not release a hold. An open hold counts against the shared pool's remaining
    capacity. Checked on the published v0.0.4 binary: one admitted prompt, then `SessionEnd` without `Stop`, left
    Held at $10.00 and Settled at $0.00 in `shared-budget status`. On 2026-11-05 the expiry was observed on the
    same binary (cap $15, hold $10): a second session's prompt was refused while the stranded hold was open and
    admitted 3661 s after it was taken. A stranded hold therefore cannot lock the pool for good; it can refuse other
    sessions' prompts for up to an hour when the remaining capacity is smaller than one more hold. Libra's own
    admission decision is what is affected; no provider charge is created or avoided by it. Tracked in HORO-2440.
15. `integrations/claude-code/README.md` in the tag says Claude Code's `Stop` and `PostToolUse` payloads include a
    `model` field. On Claude Code 2.1.306 they do not (observed on a real host). The receipt's `model` is therefore
    empty for Claude Code turns. The settled cost is unaffected: usage is priced from the per-message model in the
    transcript. The current README states this (HORO-2442).

16. The notes say the interactive Claude Code run used a network-deny sandbox. The corrected sandbox profile of that
    run (2026-10-28) is retained and, re-run on 2026-11-05, refuses an external host, an external IP and any loopback
    port other than the one fake upstream. The per-run egress probe receipts, however, were transcribed by the producer
    rather than captured by a tool, and an earlier wildcard profile failed to deny and was discarded. The claim stands;
    its per-run proof is producer-attested.
17. `docs/adr/0026-local-monthly-shared-budget.md` reports a Stop-flush measurement (36 Stops: 36 of 36 flat-hold
    settlements before the wait, 0 of 36 after). The original recorder logs are not in the tag. On 2026-11-05 the
    published binary was driven by a real Claude Code 2.1.306 (`-p`, fake local upstream, 28 Stops: fresh, resumed and
    tool turns): with the default wait 0 of 28 settled at the flat hold; with the wait disabled
    (`LIBRA_GOVERNOR_STOP_FLUSH_WAIT_MS=0`) 27 of 28 did. The direction and size of the effect reproduce; the p50/p90
    latency figures were not re-measured.

18. **(Release body)** `libra-governor gateway status` can print `State: running`, `Monetary cap: ENFORCED` and
    `Pre-spend refusal: yes`, and `libra-governor doctor` can print `[ok] gateway: gateway configured and running`,
    after the optional gateway failed to start (HORO-2424). Reproduced on the published binary 2026-11-05 with a
    credential command that prints nothing: `daemon.log` logged `gateway disabled: startup failed ...`, no listener
    existed, and a probe of `/api/hello` could not connect, while both commands still said running. The gateway is
    optional and off by default; it is available, but its status output is not reliable after a startup failure.
    To check that it is serving, look in `daemon.log` for `gateway listening on <address>` (a failed start logs
    `gateway disabled: ...`) or confirm a listener with `lsof -nP -iTCP:<port> -sTCP:LISTEN`. A healthy start showed one
    listener and `200` from `/api/hello`. Not corrected in the binary; tracked for v0.0.5 (HORO-2424).
19. **(Known High defect, HORO-2446)** On real Claude Code 2.1.306 the published binary books every subagent at the
    flat turn hold. `hook subagent-stop` has no wait for the host's transcript flush (`hook stop` has one), so the
    subagent's transcript is still without usage when it is read, and the unmeasured fallback ($10 by default) is
    charged once per subagent and never refunded. Measured 2026-11-05 against a local fake API (no provider traffic):
    10 of 10 single-subagent runs were booked at 1000c; replaying the same payload afterwards against the flushed file
    charged 1c. Three sequential subagent turns in one session were booked $30.00; three parallel subagents in one turn
    were booked $30.00; with a $25 cap, after two subagent runs ($20 settled, $4.97 remaining) further prompts were refused. No hold was stranded (held $0.00 in every run).
    This is Libra's accounting and its admission decisions, not a provider charge. Measured against an instantaneous fake API; frequency with real provider timing is untested. Interim workaround, tested: remove
    the `SubagentStop` entry from the `hooks` section of Claude Code's `settings.json`. The subagents were then settled
    from their transcripts at the parent turn's `Stop` (1 cent each, in single, three-sequential and three-parallel
    runs), with their per-agent rows kept. The workaround was not tested with subagents that outlive the parent turn,
    and `libra-governor install` restores the hook. A lower `subagent_unmeasured_charge_usd_cents` in
    `shared-budget.json` (hand-written; `init --force` drops it) reduces the flat charge but also under-counts a
    subagent that is genuinely unmeasurable. Neither is a fix. The same behavior is present on `main` as of 2026-11-05 (the flush wait was added only to `hook session-end`). Tracked for v0.0.5 as HORO-2446.
    Interactive and `-p` runs matched.
20. **(Observed, no defect)** Real Claude Code 2.1.306, published binary, local fake API: the statusline renders in the
    interactive footer (`libra: -` before the first turn, `libra: idle | budget $0.01/$50 (1%)` after one); `/compact`
    fires `PreCompact`, completes without error and leaves no hold (a second $10 subagent booking appeared around it in the interactive run most likely because the test harness's fake API re-issued the subagent call; compaction itself did not book it); the summarizer request's own usage is not
    separately booked, as the accounting-boundary note already says.

21. **(Optional gateway: what to rely on)** The local gateway is off by default and is not connected to the monthly
    budget. If you enable it, requests it forwards go to the provider and are billed to the credential in use as
    usual; Libra's statements about "no provider charge" in this page describe Libra's own accounting, never
    forwarded requests. Do not use `gateway status` or `doctor` alone as proof that the gateway is running or that a
    monetary cap is enforced: after some startup failures (a credential command that prints nothing, item 18, HORO-2424) both can still say running. Check
    `daemon.log` for `gateway listening on <address>` or run `lsof -nP -iTCP:<port> -sTCP:LISTEN`. Two further defects
    of the published binary: the token printed by `gateway token` ignores a custom `token_path` (item 10, HORO-2363),
    and `doctor` reports `config.json` as "parses cleanly" for a non-loopback `bind_addr` and for unknown keys such as a
    misspelled `upstream_host_allowlist` (HORO-2364). Reproduced on the published binary with a non-loopback `bind_addr`
    plus an unknown key: `doctor` said "parses cleanly"; the daemon refused the non-loopback bind and logged
    `gateway disabled`, so it fails closed (a reachable daemon makes `doctor` print an error that the gateway is configured but not running), and by code reading (not reproduced) a misspelled key such as `upstream_host_allowlist` is ignored, leaving the stricter default. All three are tracked for the next release.

## Not corrected here, still open

As of 2026-11-05: the fresh-machine install and rollback test and the hardening follow-up remain open follow-ups
and are not claimed as passed; the optional-gateway defects are open follow-ups: the token served by `gateway token`
ignores a custom `token_path` (a client using it is refused with 401), and `gateway status` can say "running" and
"Monetary cap: ENFORCED" after the gateway failed to start (HORO-2363, HORO-2424) and `doctor` accepts a non-loopback `bind_addr` and unknown keys without a warning (HORO-2364); the published binary still refuses a
non-object hook payload where the Host contract expects an identity-free event (fixed on `main`, not in this binary);
the pricing table's known errors in both directions are tracked in HORO-2443. A real Claude Code host was run
against the published binary on 2026-11-05 (hook payload shape, session header, hook timeout, settlement, interactive
statusline, subagents, `/compact`; see items 19 and 20). Not run when this page was last updated: a gateway request
forwarded to a real provider (needs a real credential and provider traffic), so the notes' statements about the forwarded
path (for example that bodies and headers are never logged) remain verified only by source reading and the refused-path
run.
