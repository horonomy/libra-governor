# Corrections to the published v0.0.4 release notes

The v0.0.4 tag, its tarball and its `docs/release-notes/v0.0.4.md` are frozen and are not
rewritten. This page records where the published notes, the tagged README and other tagged
documents are incomplete or inaccurate, so a reader of the tag can find the current,
version-specific facts. It is maintained on `main` and does not claim to be part of the tagged tree.

Status of the Release body itself: the items below marked **(Release body)** are proposed
corrections to the published GitHub Release text. They are **not** applied to the Release body
until the owner approves exact wording; this page states the facts in the meantime.

## Facts a v0.0.4 user should know (verified against the published binary, the tagged source or recorded release evidence)

1. **(Release body)** Uninstall: `libra-governor uninstall --yes` (or answering yes at its prompt)
   deletes Libra's whole state directory, including `shared-budget.json` (the monthly budget) and the
   spend ledger. Without confirmation the directory is left in place. The settings backup and
   `settings.json.horonom-write.lock` files remain next to your Claude Code settings.
2. **(Release body)** The "ten times the monthly cap" refusal applies to subagent, session-end and
   externally submitted charges. A main-turn settlement in v0.0.4 is recorded as priced even above that
   bound (the cap can go negative; later prompts are then refused). v0.0.5 candidates add a separate ceiling
   for implausible transcript usage.
3. **(Release body)** `/compact`: the one recorded observation was an over-count (booked at the flat subagent
   fallback); an under-count is possible but unobserved, so turns around `/compact` can be mis-counted in either direction. A main-transcript window larger than
   32 MiB settles at the flat hold, not only a subagent file.
4. **(Release body)** "No gateway hard cap in this release" is true for the monthly budget. The optional local
   gateway exists (off by default, configured in `config.json`) but is not connected to the monthly budget.
5. **(Release body, optional)** Model ids are matched to the pinned price table by prefix, so a newer id that
   shares a listed prefix is priced at the older entry's rates.
6. The README in the v0.0.4 tag says every hook is advisory-only and that "nothing here blocks". With a
   `shared-budget.json`, `UserPromptSubmit` can refuse a prompt and `PreToolUse` can deny a tool call.
7. The README in the v0.0.4 tag says no binary has been published and v0.0.4 is unreleased; the Apple Silicon
   tarball is attached to the v0.0.4 GitHub Release (a prerelease). See the Install section of the current README.
8. The tarball binary is ad-hoc signed and not notarized. `uninstall` prints a `cargo uninstall` hint for it
   (disclosed in the notes); delete the copied binary yourself.
9. `integrations/codex/README.md` in the tag lists Linux and Windows platforms. The only supported platform is
   Apple Silicon macOS.
10. Gateway configuration (optional, off by default): `token_path` must equal `<state_dir>/gateway.token` because `libra-governor gateway token` ignores the setting (a known defect); the
    session-binding header name and the reservation TTL cannot be set from `config.json`; there is no
    `pricing_overrides` in the gateway config (`shared-budget.json` has its own); the `x-libra-decision` list also includes `unauthorized` and `upstream_unavailable`.
    The historical ADR-0003 text still uses the old `gateway_reservation_ttl_secs` name.
11. ADR-0025 "Publication-time requirement 7" says release.yml builds three targets; the release workflow
    builds Apple Silicon (aarch64-apple-darwin) only. `docs/execution-owner-contract.md` states protocol 15 in
    its IPC section (and 22 later in the same document); the tagged protocol version is 24.

12. **(Release body)** The "Known issues" sentence says "three open dependency alerts" in `experiments/phase0`. On
    2026-11-02 GitHub shows 13 open alerts, all `filelock` in `experiments/phase0/uv.lock` (severities low to high).
    They concern a Python experiment directory that is not part of the shipped binary; the location claim stands,
    the count was wrong.
13. `uninstall` asks for the full word `yes`; `y` declines.
14. **(Behavior to know)** A turn that never reaches `Stop` (you interrupt it, Claude Code exits or crashes, or a
    `SessionEnd` arrives with no `Stop`) keeps its hold, one turn's reservation (default $10.00), until the hold
    expires after one hour (`HOLD_TTL_SECS = 3600`). `SessionEnd` charges only the records no `Stop` counted; it does
    not release a hold. While the hold is open it reduces the remaining capacity shown by `shared-budget status`
    for every session. Checked on the published v0.0.4 binary (one admitted prompt, then `SessionEnd` without `Stop`:
    Held stays $10.00 and Settled $0.00); the expiry itself was not waited for or observed in that check.

## Not corrected here, still open

As of 2026-11-05: the fresh-machine install and rollback test and the hardening follow-up remain open follow-ups
and are not claimed as passed; the optional-gateway defects (the token served by `gateway token` ignores a custom
`token_path`, and `gateway status` can say "running" after a failed startup) are open Medium follow-ups; the
published binary still refuses a non-object hook payload where the Host contract expects an identity-free event
(fixed on `main`, not in this binary). Checks that need live provider traffic or a real Claude Code host were not
run for every claim, so some statements in the release notes remain unverified.
