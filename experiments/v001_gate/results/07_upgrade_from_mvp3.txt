=== Follow-up: recovering from the stale old-protocol daemon ===

The `doctor` [error] above (protocol mismatch v7 vs v6) is real and
reproducible: upgrading the installed binary in place does NOT restart
an already-running daemon process spawned by the OLD binary. This is
expected, documented behavior -- doctor's own error text tells the user
exactly how to recover (`pkill -f "libra-governor daemon run"`), and
`scripts/install.sh` surfacing this as a nonzero exit is doctor doing
its job (real current state, not a claimed success) rather than an
install failure. Not filed as a product defect; flagged here as a real
upgrade-workflow UX finding worth a README callout: after upgrading in
place, restart any already-running daemon (or open a new Claude Code
session, whose next hook connection will surface the same mismatch and
point at the same fix).
