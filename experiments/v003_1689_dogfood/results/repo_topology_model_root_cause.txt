Verdict: sample-shape artifact, not a real estimator defect. `actual` is
monotonically increasing because this is the same session's cumulative
duration, re-finalized at every Stop event. Each estimate's p90 bound tracks
roughly one step behind the growing actual (e.g. actual=780/p90=775,
actual=851/p90=846) because the estimator's own history is built from this
same monotonic sequence's prior values. A quantile estimator fed a
monotonically-increasing series will structurally undershoot every new
point by construction -- this is not evidence that the conditional/bucketed
estimator mis-predicts real, independent task durations. No Jira follow-up
filed for "estimator defect"; the real, generalizable finding is
methodological: repeatedly re-finalizing one long-running session at growing
cumulative durations is not a valid way to test a duration-quantile
estimator's real-world accuracy, regardless of which product this pattern
shows up in.
