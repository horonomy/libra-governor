# MVP 2.0 Calibration Evidence

This directory holds the real, committed output of `libra-governor calibration report`
run against a real local ledger, generated by driving 3 real preflight -> tool-call ->
stop cycles through the actual compiled binary against a fresh state directory.

## Result (2026-09-18)

See `results/calibration_report.txt`. Headline: **insufficient data** — n=2 non-cold-start
calibration pairs exist locally (1 cold-start row correctly dropped), well below the
calibration floor of >= 30 non-cold-start pairs with >= 15 distinct actual durations in
a single non-Global bucket tier.

This is the correct, honest result for a pre-launch product with zero real end-users.
It is not a placeholder or a failure — it is what the calibration infrastructure is
supposed to report when there isn't yet enough real trajectory data to calibrate against.
Fabricating a coverage percentage from this data (or from HORO-1127's 34-row synthetic
corpus, whose durations are all exactly 0.0 and therefore not real evidence either) would
violate the campaign's no-fabrication invariant.

## When this becomes real evidence

Per HORO-1132's design decision: once >= 30 non-cold-start calibration pairs exist with
>= 15 distinct `actual_duration_secs` values within a single non-Global bucket tier, a
re-run of `libra-governor calibration report` will report real empirical coverage and
admission-replay numbers instead of "insufficient data". This is expected to happen
during v0.0.1 Developer Preview real usage, not before — MVP 2.0's release gate
(HORO-1135) must not block on data that only real users can produce.

## Reproduce

```
export LIBRA_GOVERNOR_STATE_DIR=/tmp/some-fresh-dir
libra-governor hook user-prompt-submit < payload.json   # repeat for real tasks
libra-governor hook post-tool-use < payload.json        # per tool call
libra-governor hook stop < payload.json                 # finalizes a receipt
libra-governor calibration report
```
